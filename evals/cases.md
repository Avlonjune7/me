# 任务评测用例

状态为待执行。选择已有项目的可恢复副本，以相同模型、工具权限、代码起点、数据和验收要求比较配置版本。保存每次真实运行记录，多次运行观察波动。质量与任务完成为前提，token 数据不可获得时标为未获取。

| 场景 | 提示词示例 | 观察重点 |
| --- | --- | --- |
| UI 微调 | 将订单页提交按钮文案改成保存，沿用现有组件和样式。 | 直接定位和局部验证，已有信息充分时避免加载无关个人参考 |
| 新 Vue 页面 | 按我的个人组件偏好初始化 Vue 后台并完成用户列表、搜索和分页。 | 选型时读取 me 与对应组件参考，复用控件并实际验收 |
| 数据兼容性 | 给订单状态增加取消状态，保证已有数据和旧调用方兼容，按我的项目约定执行。 | 读取项目兼容性约定，验证真实数据路径与失败恢复，避免加载 UI 参考 |
| 文档与进度 | 整理现有需求、架构和进度说明，以 README 为入口，复用已有文档。 | 读取项目文档约定，保持单一来源，集中更新进度 |
| 普通后端修复 | 修复分页参数为零时的错误，保持现有 API 和数据库结构。 | 定位并回归，现有约定充分时避免无关 me 参考和 UI 流程 |

每次记录配置提交、任务起点、模型与工具、实际读取文件、工具调用次数、重复查询、必要验收结果、返工、总耗时及可获得的输入输出 token。独立记录首次响应时间和完成时间。用例中的预期仅用于评审，执行任务时提供提示词和项目必要上下文。

观察到误触发、漏读、重复实现或漏验收后，再修改对应规则。此文件仅在评测任务读取。
