# 组件与设计系统

本文件是 UI 复用规则的唯一完整来源，其他文件只做引用。

## 动手前

- 确认技术栈、项目组件库入口和本次涉及的控件。组件库入口即统一组件层，可以是本地公共目录、共享包或设计系统官方导出，以项目配置为准。
- 先查项目统一入口，仍有缺口再定向查对应版本文档或 CLI。按功能、行为和场景匹配，不因没有同名组件就判定缺失。
- 局部修改只查相关组件、公共入口和受影响调用；组件迁移、整体统一或发现混用时再扩大检查。

## 复用与扩展

- 页面、业务组件和局部微调都必须复用已有且满足需求的公共 UI 能力，范围包括：操作与表单、内容展示、反馈与浮层、导航、布局，以及焦点、键盘、滚动锁定、拖拽和加载/空/错误/禁用等交互状态。
- 控件视觉通过组件 API、公共变体或主题 Token 调整，禁止用页面级覆盖重做已有控件。页面编排可用 Flex、Grid 和项目间距约定，但不借布局重做控件外观。
- 搜索框默认不使用内阴影。
- 缺少控件时先查所用体系的官方能力；确需自定义时在统一组件层最小扩展，并说明原因。
- 发现多套实现时，本次改动收敛到已确定的目标体系。

## 体系细节

- Astryx：接入前确认 `react` 与 `react-dom` 满足 React 19+ 及所选版本的 peer dependencies，低版本先评估升级范围。实现遵循其 skill 与项目版本文档。
- shadcn-vue：基于 Reka UI，底层交互封装在统一组件层，页面和业务组件通过统一入口使用；旧项目依赖以实际版本为准。
- 框架升级或整体替换先评估兼容性与成本，超出任务范围先确认。
- React 复杂组件设计与重构按需使用 vercel-composition-patterns。

## 设计任务

- 用户要求界面设计、重设计、体验规划、精修或视觉与交互评审时使用 Impeccable，按其流程执行。其他 UI 任务直接用现有组件实现，不启动方向探索、素材制作或独立评审。
- 后台与工具界面偏好简洁、专业、高信息密度；阅读界面优先清晰舒适；品牌与展示页面按受众发挥视觉表达。用户明确的品牌和设计要求优先。
- 精修保持现有视觉方向；重设计可在授权范围内更新主题与视觉系统。
- PRODUCT.md 承载产品事实，DESIGN.md 记录已确认的视觉系统，PRD 保留需求与验收；复用已确认信息并链接来源。
