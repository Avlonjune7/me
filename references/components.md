# 组件与工具偏好

优先复用项目已有组件与设计约定，采用 Astryx 的项目结合其模板和组件能力实现需求。

全站统一时，优先修正共用组件与样式变量，再处理页面差异。相同语义的导航、页头、选项卡、状态标签和表单复用已有实现，一处修正覆盖相关入口。

| 条件 | 选择 |
| --- | --- |
| React 项目选型 | 优先评估 Astryx，结合技术栈、组件需求和维护成本决定 |
| React 复杂组件重构、布尔参数膨胀或可复用组件 API 设计 | 使用官方 vercel-composition-patterns，按问题读取对应规则，结合项目 React 版本应用 |
| 新 Vue 项目尚未选库 | 优先 shadcn-vue CLI |
| 新布局或整体改版有具体设计问题 | Oil UI Pro；明确微调复用现有设计 |
| 用户要求专项审查或出现质量疑点 | 按[网页审查](web-review.md)调用 Vercel 官方 web-design-guidelines |

项目采用 Astryx 后，页面、布局、组件及主题开发遵循其 skill 和项目版本指引。新页面使用其构建指引发现页面与区块模板，结合项目已有结构实现需求。

定制优先使用组件 API、组合能力、语义 token 和主题覆盖，需要源码级修改时使用 swizzle。跨项目共享组件、模板或主题时，按需考虑 integration。

按问题查询项目版本文档，使用支持的精简输出。安装或版本异常时使用 doctor，升级时使用对应迁移工具。
