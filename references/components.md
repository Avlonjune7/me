# 组件与设计系统

选型与迁移遵循主入口约定，每个项目在已确认体系内统一主题、组件和交互。

- 涉及框架升级或整体替换时评估兼容性与成本，超出任务范围时先确认。
- 动手前确认技术栈、项目组件库入口及本次涉及的控件，复用已确认且仍有效的信息。项目组件库入口是统一组件层的使用入口，可以是本地公共目录、共享包或设计系统官方导出，以项目实际配置为准。
- 发现多套实现时，将本次改动收敛到已确定的目标体系。shadcn-vue 基于 Reka UI，底层交互封装在统一组件层内，页面和业务组件通过统一入口使用控件；旧项目的依赖关系以实际版本为准。
- 接入 Astryx 前确认 `react` 与 `react-dom` 均满足 React 19+ 及所选 Astryx 版本的 peer dependencies，低版本项目先评估升级兼容性与范围。Astryx 项目遵循其 skill 和项目版本文档；Vue 项目遵循 shadcn-vue 对应版本文档，通过 shadcn-vue 的主题与组件保持全站一致。依赖兼容性、安装和深度定制方式按需查询。
- 后台与工具界面偏好简洁、专业和高信息密度，阅读界面优先清晰与舒适，品牌、营销与展示页面按目标受众发挥视觉表达。具体模式由 Impeccable 按页面用途选择，用户明确的品牌和设计要求优先。
- 复用已有页面、截图与素材，设计所需的案例研究、图像、动效及方向探索按目标和所选流程展开，读取与产出聚焦本次设计问题。

## 设计任务分工

- Impeccable 主导新界面、重设计、体验规划、视觉精修和评审，按目标选择对应指引。组件与主题实现遵循项目已确认体系，通过组件 API、公共变体和 Token 落地，确认能力缺口后允许必要扩展。重设计可在授权范围内更新主题和视觉系统，精修遵循现有视觉方向。
- 改法明确的局部任务直接复用并验证。进入 Impeccable 流程后，按该流程完成必要的方向探索、方案选择、素材制作、独立评审、检测和实际页面验收；尊重其确认点与适用的降级要求。复用有效证据，批量修正与复测，避免重复启动无关流程。
- 遵循 Impeccable 的 context 与文档流程。PRODUCT.md 承载工具所需产品事实，DESIGN.md 及配套文件记录确认后的视觉系统，PRD 保留详细需求与验收。复用已确认信息并链接来源，必要的摘要保持一致，文档创建与覆盖遵循对应确认流程。

## 复用范围与扩展边界

以项目实现和所用库当前版本的实际能力为准，包括组件、变体、组合 API、Hooks 和页面模板。先查项目统一入口，本次需求仍有缺口时再定向查对应版本文档或 CLI，复用有效查询结果。用户口语或组件名称不同，按功能、行为和使用场景匹配，不能仅因没有同名组件就判断缺失。

以下类别按本次需求选取。局部修改仅检查相关组件、公共入口及受影响调用；组件迁移、整体统一或发现混用与影响扩大时，按相关范围扩展检查。

- 操作与表单，如按钮、输入、选择、上传与校验。
- 内容展示，如表格、列表、卡片、徽标、树与媒体展示。
- 反馈与浮层，如弹窗、抽屉、轻提示、气泡与加载反馈。
- 导航，如菜单、标签页、面包屑、分页与命令面板。
- 布局，如容器、栅格、应用外壳、滚动区域与分栏。
- 交互与状态，如键盘操作、焦点管理、滚动锁定、拖拽及加载、空、错误、禁用状态。

页面区块和业务组件先查项目已有实现及适用模板，缺少时用现有基础控件组合。布局优先复用适用的容器、栅格和外壳，缺口可用 Flex、Grid 及项目样式完成页面编排，避免借布局重做已有控件外观。

控件视觉优先使用组件 API、公共变体和主题 Token，页面布局使用项目间距等设计约定。交互与状态复用对应组件或 Hooks，覆盖本次流程涉及的焦点、键盘和异步反馈。确认现有能力无法满足需求后，在现有体系内最小扩展；可复用控件与行为进入统一组件层，并说明扩展原因。

React 复杂组件设计与重构按需使用 vercel-composition-patterns。
