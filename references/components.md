# 组件与设计系统

以 Astryx 设计语言统一视觉，React 默认使用 Astryx，Vue 默认使用 shadcn-vue。用户当次要求和项目明确约定优先。

- 新项目按上述体系初始化。已有项目先确认本次目标体系及迁移范围，复用可适配的公共组件与业务逻辑；涉及框架升级或整体替换时评估兼容性与成本，超出任务范围时先确认。
- 动手前确认技术栈、实际组件入口及本次涉及的控件，复用已确认信息。统一组件层可以是项目公共目录、共享包或设计系统官方导出，入口以项目配置为准。
- 基础控件按主入口复用约束执行，业务组件通过其组合实现。官方能力不足时，扩展统一组件层，定制优先使用组件 API、公共变体和主题 Token。
- 发现多套实现时，将本次改动收敛到已确定的目标体系。组件库与其底层交互依赖按项目封装关系识别，页面通过统一组件入口使用。
- Astryx 项目遵循其 skill 和项目版本文档；Vue 项目遵循 shadcn-vue 对应版本文档，通过自身主题与组件落实适用的 Astryx 视觉原则。依赖兼容性、安装和深度定制方式按需查询。
- 产品界面偏好简洁、专业、高信息密度。默认深化一个方向，用户明确要求比较时再提供多方案。
- 仅在用户明确要求外部案例时查阅，优先复用已有页面或截图，参考用于布局与流程，视觉实现遵循统一基准。

React 复杂组件设计与重构按需使用 vercel-composition-patterns。
