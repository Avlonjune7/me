# 验证偏好

- 修复线上问题时，用能复现故障的代表数据验证相关操作；现有测试无法覆盖本次故障且有回归风险时补充测试。
- 全站 UI/UX 统一时覆盖所有目标页面。用户要求统一组件体系时，核对基础控件的实际来源、使用方式及主题一致性。完成约定范围内的迁移后才可标记完成；遗留实现须列明位置、原因及未完成范围。
- UI 交付前检查改动文件中的重复基础控件、独立基础样式及绕过公共主题的页面覆盖，修正后交付，说明必要的自定义实现与实际遗留问题。
- Astryx 页面按项目版本审查指引（`astryx docs is-my-code-good`）验收；Vue 页面依据 shadcn-vue 的实际组件配置与文档，核对目标主题、控件状态和交互。

- 相关工具可用且适合项目时，sh/bash 用 ShellCheck，PowerShell 用 PSScriptAnalyzer，GitHub Actions 用 actionlint。缺失工具是否安装由项目要求和具体验证需求决定。
- 浏览器任务开始时按登录态与验证目标选择工具。真实登录态的线上页面操作、表单和接口关联排查优先 BrowserSkill，先读取其技能；本地页面与独立浏览器测试优先 Playwright CLI。用户指定工具时遵循用户要求。首选工具不可用或缺少所需能力时，使用适合的已连接工具并说明实际原因。同一页面由一个工具控制，结束时按对应技能清理本任务会话。
- 浏览器排查聚焦目标区域及相关接口字段，执行细节遵循对应技能。滚动问题在实际容器内验证滚轮行为。UI/UX 性能优化按[页面性能](performance.md)比较改动前后的代表性场景。
- 涉及布局、响应式或交互变化时，实际运行并检查受影响页面与关键状态。局部改动验证受影响入口，公共组件改动抽查代表性使用页面。新增影响、失败、未解决疑点或用户要求触发扩大验证。
