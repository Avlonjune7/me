# 项目约定

## 开发与环境

- 正式功能必须接入真实接口与数据；原型、测试替身及占位明确标识，交付时说明未接通范围。
- 数据库、API 和公共协议变更必须评估调用方与历史数据兼容性，按影响明确迁移、失败恢复及适用的回滚方式。
- 反复手动执行的稳定步骤按需固化到已有脚本，并在 README 记录入口。环境正常且依赖配置未变时直接复用，异常仅检查相关服务；跨环境访问以实际检查为准。
- 多会话并行修改同一项目时，按冲突风险使用独立分支和 worktree，明确端口与服务归属，共享数据另行评估。

## 项目文档与进度

- 要求整理规范时维护项目的 AGENTS.md。项目采用 Astryx 时，允许其初始化与升级工具维护自身生成的指引区块。已有 DESIGN.md 继续承载设计决定，其他文档通过链接引用。
- 沿用已有等效文档。持续开发的项目以 README.md 为入口，集中运行、环境配置和部署说明，按需维护 docs/PRD.md（需求与验收）、docs/ARCHITECTURE.md（架构）和 docs/PROGRESS.md（计划与进度）。已有 PLAN.md 可继续承担进度记录，保持单一来源。
- 进度文档仅在状态变化或交接时集中更新，简记分支/提交、完成范围、验证与缺口、下一步及必要命令。需求、架构或运行方式变化时同步对应说明。
- 文档记录稳定配置，运行状态以现场检查为准，凭据使用项目既有方式保存。
